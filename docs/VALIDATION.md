# 当前交付验证记录

日期: 2026-11-07. 新协议 QT2 / QRF1. 本轮只做本地交付, 未推送远端.

## 核心与视频

Windows CPython 3.12.4 和 Rocky Linux 8 / CPython 3.12.15 均已通过 43 项单元/集成测试, 双端 Tk 窗口工作流验收也均通过.

- 精确复现三源块 seed=10/7/3 的 2/3 停滞, 修复后无需再收包即可恢复全部; 覆盖重复、乱序、丢包、padding=0、重复读取结果.
- 实际生成有跳跃移动、重复画面、空白遮挡的 MP4, 验证 ROI 丢失后同帧全图重找和顺序解析.
- 实际 MP4 流程: 首次只含隔块源数据 → 保存现场 → 加载新接收对象 → 重复视频进度不变 → 生成请求 → 定向源块补传 MP4 → 追加导入 → 原始内容逐字节一致、最终 SHA-256 通过. 重复补传仍正确.
- 待解 LT 关系、去重状态保存后重开, 加入原始块后继续消元完成; 冻结发送任务不受原文件后来修改影响.
- 反馈覆盖零缺块、接近一半、几乎全缺、全缺、连续、零散、随机分布, 两种方向、位图及自动实际最短长度往返一致; 局部选区精确到缺失源块.
- 损坏/截断现场、保存替换失败、损坏编码包、错误任务、非法编号、最终身份/文件校验失败均拒绝或明确报告, 不虚报完成/保存成功.
- 空文件、不同分块参数身份、分组图范围/颜色、多轮补传、后台发送取消/报错、录屏中不调用二维码识别均覆盖.
- 屏幕采集测试用模拟 MSS 输入真实视频帧, 写出真实 MP4 后交给同一解析器恢复; 不代表实际显示器/摄像头采样率已经验证.
- 用户明确要求的旧视频一次性入口单独验证, 不合并新任务.

本轮最终 ZIP 位于 `dist/current`. 每个 ZIP 附 SHA-256, 内有 BUILD-INFO.json 源码摘要和实际宿主/依赖信息.
| 交付 | 实际验证 |
|---|---|
| Windows x64 发送/接收便携 ZIP | 已构建; 解压隔离开发路径后 GUI/CLI 启动、发送码内容、冻结任务定向补传、接收现场重开/请求导出/补传 MP4 追加和错误状态均通过 |
| Linux x64 发送/接收便携 ZIP | Rocky Linux 8 实构; Xvfb 中 GUI/CLI 及相同内容工作流验收通过 |
| 无 Python 的干净 Rocky Linux 8 | 接收 MP4 成功; Windows 生成的纯 LT 喷泉视频经 Linux 成品恢复, 最终文件校验通过; 临时 Xvfb 空白屏幕录制保存真实 MP4 并进入同一解析器, 如实报告无任务 |
| Windows/Linux x64 双角色离线源码包 | 已生成; 解压安装和运行验收见本轮交付报告 |
| Windows x86 离线依赖源码包 | 已下载、校验并打包; 无 32 位运行环境, 未执行 |

Linux 打包补入固定基线的 XCB/OpenGL 分派客户端库, 并为 MSS 的 ctypes 库发现配置打包运行钩子, 不携带显卡驱动或 glibc.
干净无字体 Linux 镜像的 GUI 启动失败已确认是字体环境缺失; GUI 需要可用的系统字体/字体配置和图形服务. 已验证的 Xvfb 环境带 fontconfig/DejaVu. 未宣称无桌面、无字体的裸系统能直接显示中文窗口.
旧轮次 `dist` 根目录文件不属于本次交付.

Windows x86 有 CI 工程和 CPython 3.12 离线依赖包, 本机无 32 位 Python, 未构建/运行 x86 exe.
Linux x86 没有当前 Pillow/OpenCV/NumPy 的现成 wheels, 未交付 32 位 Linux 成品, 不能用 x64 改名冒充.
新 CI 尚未推送/运行. 不宣称 Ubuntu、Debian、RHEL 各版本均逐一实测.

## 限制

合成 MP4 和模拟录屏可验证协议/软件流程, 不能证明播放器、实际屏幕采集、摄像头、不同压缩质量都一次恢复.
记录缺失或画面严重损坏时必须追加接收/定向补传. 当前逐帧解析不做节奏同步降采样, 不做改变参数的回看重试.
Linux 便携基线为 glibc >= 2.28 / x64, GUI 需要图形服务与可用字体/字体配置. MSS 录屏需要 X11; Wayland 可外部录制后导入.
文件与现场均在内存中处理, 没有进行超大文件压力/性能基准测试. 最终全局校验失败时不推测坏块归属或覆盖原状态.
CRC/SHA 用于发现损坏和防混任务, 没有发送者认证/加密.
