# 新手使用说明

## 选择程序

发送电脑打开 `QRSend.exe` (Linux: `QRSend`), 接收电脑打开 `QRReceiver.exe` (Linux: `QRReceiver`).
完整解压对应 ZIP, 不要单独复制一个可执行文件. 无法安装 Python 时优先选便携包.
Linux x64 基线为 glibc >= 2.28, 需要相应动态加载器; GUI 还需图形服务、可用字体和字体配置, 中文显示需系统提供中文字形. 不适用 Alpine/musl、RHEL 7 或 32 位 Linux.
不是所有 Linux 都能直接运行; [已验证目标](VALIDATION.md) 与仅提供构建工程的目标分开记录.

如果使用源码, 电脑须已有匹配的 Python 3.10-3.12; GUI 还需 Tk, Linux 录屏还需可访问的 X11 桌面.
源码包中先运行 `install.cmd` / `bash install.sh`; 离线包加 `--offline`, 不访问网络.
wheels 不含系统 Python/Tk/venv. 这些也无法安装时使用便携包.
安装后 Windows 用 `send.cmd` / `receive.cmd`, Linux 用 `bash send.sh` / `bash receive.sh`.
命令行入口为相应的 `send_cli` / `receive_cli` 脚本. 仓库直接使用时按 requirements 安装后运行相应 `.py`.

## 发送第一次完整任务

点击“新建发送任务”, 选择一个文件, 保存 `.qrtx` 发送任务. 多个文件先打成一个 ZIP.
任务冻结具体编码数据、文件摘要和分块参数; 原文件之后被修改或移走不会改变已保存任务.
**请保留这份原发送任务用于后续补传.** 打开原任务不会重新读取、压缩文件.
窗口默认源块 256 字节, 每码显示 150 毫秒, 二维码边长 600; 大小须能完整放进屏幕.

点击“开始发送”. 二维码下方进度条显示“第 N 轮”和当前码/本轮总码数.
开头为本轮第 1 码, 末尾标注本轮结束; 下一轮数字递增, 颜色切换.
每个完整普通轮次覆盖该文件全部源块, 再发 50% 喷泉冗余包. 下一轮产生新的喷泉包.
补传轮次则只包含本次请求的源块. 进度条的码数不是文件源块总数, 接收端的恢复数量也不是视频帧数.
录到完整一轮且每个源码都清楚可读, 才有直接还原的条件; 遮挡、模糊、漏采仍可能需要续收或补传.

## 接收 MP4 或录制屏幕

先选接收目录. 初次直接点“导入/追加 MP4”, 读到首个有效 QT2 包后建立任务.
离线解析按实际处理能力顺序读帧, 不追赶播放时间, 不因识别慢跳过尚未处理帧.
完全相同的灰度画面跳过重复识别; 已接纳编码包按内容去重. 恢复并校验完成后可提前结束扫描.
识别会跟随二维码的位置; 局部识别失败时立即搜索同一完整帧, 不要求二维码始终停在同一像素位置.

接收正在播放的内容时, 点“录制屏幕”, 指定 MP4 保存位置和屏幕编号. 默认 30 帧/秒.
点击“停止录制并解析”, 程序先结束录制、保存并确认视频可读取, 再使用同一套逐帧解析逻辑.
录制期间不进行二维码识别. 实际采集帧数、时间和帧率记录在界面日志; 保存失败会明确提示.
解析期间点击同一个停止按钮会取消解析并保存已有接收进度; 稍后可重新导入这个视频补扫.

30 帧/秒、每码 150 毫秒大约给一个码 4-5 次采样机会, 不代表保证识别成功.
录制设备、画面尺寸和编码速度会降低实际采样率; 请确保二维码完整、留白清楚、不过度缩小, 避免重压缩和运动模糊.
能录得更慢时, 延长发送端每码显示时间. 可调小源块降低二维码密度, 但码数会增加.
逐帧解析不能补回录制时没有采集到的画面, 同样参数倒回重扫也不保证新增信息.
Linux 录屏基于 MSS/X11; Wayland 或无屏幕权限时可以用系统工具录制, 再导入 MP4.

## 保存现场、关闭后继续

每轮解析结束、取消或读取出错后, 只要已有有效任务就尝试保存现场.
默认位置为接收目录 `tasks/<任务标识>_<时间>.qrrx`, 后续沿用同一文件.
保存的内容包括已恢复块、待解喷泉关系、去重记录、处理过的视频摘要、日志和编码参数.
界面明确显示现场是否真正保存成功, 保存失败时请用“另存现场”更换可写目录重试.
关闭窗口时会先停止工作、保存现场/录制视频, 保存失败会保留窗口提示处理.

重启后点击“继续原任务”打开 `.qrrx`, 再“导入/追加 MP4”. 可以跨视频、多轮累积.
同一个视频重复导入会保留原进度; 同一个包跨轮次收到也不会重复计数. 已完成时重复导入不会重复命名导出同一文件.
“新建/重置任务”先保存原现场, 再新建空任务, 原现场文件仍保留. 其他任务包会被拒绝并计入异常原因.
任务身份绑定冻结后的实际编码数据及分块大小, 不按文件名或块数合并.

## 看分块图并生成补传请求

图中最多 100 格, 按连续范围映射真实源块, 小任务会更少. 显示分组不改变传输块大小.
灰色是尚未恢复; 黄色是本组部分源块恢复; 绿色是本组全恢复.
红色可能是“本轮结束仍待补传”, 也可能是明确的源块载荷冲突; 双击查看具体原因、范围、数量和未恢复编号.
编号从 0 开始. 无法识别的二维码无法定位到源块, 不会据此随意把某一格判为校验错误.

程序先剥皮, 再对残余方程做 GF(2) 高斯消元, 然后按仍未恢复的原始源块生成反馈.
满秩时无需再补包; 欠秩时保留关系并只恢复能唯一确定的源块. 方程数量不等于秩, 未恢复也不等于从未收到相关信息.
视频结束日志显示高斯新增恢复量和求解前残余方程秩. 重开现场后若已能完整求解, 会校验并保存文件.
默认“自动最短”比较缺块描述、已恢复块描述和位图的完整补传码长度, 可手动选择:

- 缺块: 列出未恢复源块, 发送端补这些块.
- 成功: 列出已恢复源块, 发送端补选区内其余块.
- 位图: 按源块编号从小到大, 1=待补传, 0=本次不补传; 字节内低位在前.
- 全部重发: 明确选择才发送全部源块, 接收现场继续保留. 不会因补传码压缩效果差自动启用.

点击“生成补传码”覆盖整个任务; 或单击选中未完成区域后点“从选中区域生成”.
选区最终请求精确到尚未恢复源块, 不把整格重发. 全部重发模式不能与局部选区一起使用.
“复制单行补传码”只复制机器码, 不带日志. 也可“导出补传请求”保存 `.qrreq` 文件.
补传码含版本、完整任务标识、集合语义和 CRC. 截断、损坏、非法编号或错误任务会明确报错.
Base64 只用于可复制文本封装; 实际长度收益来自差分/区间/位图和可选 zlib, 没有使用未确认的“MD3/UU”算法.

## 定向补发并追加恢复

发送端“打开原发送任务”, 粘贴码并点“校验并使用补传码”, 或导入 `.qrreq`.
核对窗口中的将补发源块数和块载荷字节数. 字节数包括末块填充, 不含二维码包头和显示冗余.
点击开始发送, 每轮只轮播这些源块. 请求为零块时提示无需补传.
接收端继续原任务, 导入新录制的补传视频, 有效块合并后继续消元. 重复补传和乱序不会让进度倒退.
如果还不完整, 根据最新现场重新生成补传请求. 只有完整编码数据身份、原文件大小和 SHA-256 都通过后才显示完成并写出文件.
每轮日志显示任务、总源块、已恢复、未恢复、本轮新增、异常包和保存结果, 提示下一步追加视频或传递补传码.
最终校验失败不会当作完成, 会保留现场并提示错误; 无法据此确定具体坏块, 不自动改写已恢复数据.

## 旧视频入口

以前录制的 `seed|块数|padding|数据` 格式请点“旧视频一次性解析”, 或加 `--legacy`.
每次使用独立状态, 不并入 QT2 现场, 不生成可靠补传请求. 旧协议没有逐包 CRC 或最终文件摘要, 请自行核对原文件内容.

## 命令行示例

源码用 `python qrcode_tx.py` / `python qrcode_rx.py`; 便携包替换为 `QRSendCLI.exe` / `QRReceiveCLI.exe` (Linux 无 exe 后缀).

```bash
python qrcode_tx.py example.zip --task send.qrtx --size 600 -i 150
python qrcode_rx.py --video first.mp4 --task receive.qrrx --output-dir received --request-out repair.qrreq
python qrcode_tx.py --task send.qrtx --repair repair.qrreq
python qrcode_rx.py --video repair.mp4 --task receive.qrrx --output-dir received
# 仅从现场导出请求
python qrcode_rx.py --task receive.qrrx --request-out repair.qrreq --request-mode auto
# 先录制, 60 秒后结束并解析; 不加 seconds 时 Ctrl+C 结束录制
python qrcode_rx.py --record-screen capture.mp4 --fps 30 --seconds 60 --task receive.qrrx
# 导出一轮 PNG (输出目录须为空)
python qrcode_tx.py example.zip --task send.qrtx --no-display --output qr-images
python qrcode_rx.py --legacy --video old.mp4
```

接收退出码: 0=最终校验通过 (旧入口为有文件导出), 2=数据不足, 1=读取/校验/保存错误, 130=取消.
补传码打印到标准输出, 说明和错误写到标准错误. `--help` 列出参数.
当前数据和现场在内存中处理, 不适合超大文件; 需要时先按业务拆分文件分别建立任务, 不能混用不同任务.
程序不能保证任意录制一次恢复; 剩余未恢复块和补传请求才是后续操作依据.
